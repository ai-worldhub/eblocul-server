# Журнал

## Что пишется само

- О каждом HTTP-запросе — одна запись `http.request` в конце: `requestId`, `method`,
  шаблон маршрута (`/api/v1/houses/:houseId`, а не реальный путь), `status`, `durationMs`, `userId`.
- Тело, query, заголовки и IP не пишутся. `GET /health` и `GET /metrics` не пишутся.
- Необработанная ошибка — запись `http.unhandled_error`: тип, код и строки стека.
  Текст сообщения ошибки не пишется никогда: библиотеки вставляют в него аргументы вызова.

## Что запрещено писать

Имена, телефоны, email, номера машин, адреса и номера квартир; текст сообщений, объявлений
и заявок; коды входа и SMS-коды; имена и содержимое файлов; токены и ключи.
В полях записи — только идентификаторы, числа и значения enum.

## Как писать событие

- Только через `EventLogger`. `Logger` из Nest, `pino` и `console` в модулях не используются.
- Имя события — `<модуль>.<что_случилось>`: `access.code_issued`. Текстового сообщения нет: событие и есть сообщение.
- Событие объявляется в `application/<модуль>.log-events.ts` расширением `LogEvents`;
  сервис импортирует этот файл: `import './access.log-events.ts';`.
- В файле должен быть хотя бы один `import` или `export {}`: без него это не расширение, а новое объявление, и `tsc` выдаст ошибку.

```ts
export {};

declare module '../../../shared/logging/log-events.ts' {
    interface LogEvents {
        'access.code_issued': { codeId: string; unitId: string };
    }
}

this._events.info('access.code_issued', { codeId, unitId });
```

## Уровни

- `error` — ответ 500, упавшая фоновая задача.
- `warn` — требует внимания, но не сломалось.
- `info` — запрос завершён, доменное событие. Ответы 4xx — тоже `info`: это ошибка клиента.
- `debug` — только локально.

## Id запроса

Клиент передаёт `X-Request-Id` с UUID; если заголовка нет или это не UUID, сервер создаёт свой.
Id возвращается в заголовке ответа и в теле ошибки, и его получают все записи внутри запроса.
В модуле он доступен через `EventLogger.requestId()`.

## Страховка

Перед записью значение любого поля, в имени которого есть `password`, `secret`, `salt`,
`api_key`, `authorization`, `cookie` или которое оканчивается на `token`, заменяется на
`[redacted]` — на любой глубине до восьми уровней. Это страховка, а не разрешение класть такие поля в события.

## Проверяется автоматически

- `tsc`: неизвестное событие, лишнее поле, неверный тип поля.
- oxlint: прямые импорты логгеров и `console`.
- `test/e2e/logging/logging.e2e-spec.ts`: одна запись на запрос с шаблоном маршрута и без данных запроса;
  `health` и `metrics` не пишутся; `X-Request-Id` принимается только как UUID и попадает в события и тело ошибки;
  500 пишется без текста сообщения; поля с секретными именами маскируются.
- `test/unit/logging/`: маскировка на глубине и формат строки для локальной работы.

## Не проверяется

- Персональные данные в поле с обычным именем: `phone: string` пройдёт и `tsc`, и маскировку.
- Имена событий и выбор уровня.
