# Тесты

## Раскладка

```
test/
  unit/<тема>/*.spec.ts          без базы и без Nest-приложения
  e2e/<тема>/*.e2e-spec.ts       настоящая база; через HTTP, если у модуля он есть
  factories/                     фабрики тестовых данных, по файлу на модуль
  utils/                         оснастка
  setup/e2e.global-setup.ts      миграции перед e2e
```

`npm test` запускает `unit`, `npm run test:e2e` — `e2e`.

## Что чем проверять

- **Правила entity** — unit, без Nest и базы, на фиксированных датах.
- **Сценарий эндпоинта** — e2e: успешный путь и каждая ошибка со статусом и `code`.
- **Сценарий модуля без HTTP** — e2e через его сервисы на настоящей базе: успешный путь и ошибки, которые решают сервис и база, —
  не найдено, занято, чужое, нарушен порядок. Ошибка правила entity остаётся в unit: в e2e её не повторяют.
- **Запрос, который обязан идти по индексу**, — e2e на данных, созданных в самом тесте: тест читает план (`planOf`).
  Требуется то, что устойчиво между прогонами и версиями PostgreSQL: по индексу, не подряд, не больше N строк.
  Индекс называется по имени там, где выбор у планировщика один.
- **Одновременность** — e2e с принудительным пересечением (`runOverlapped`): первая транзакция остаётся открытой,
  пока вторая не встанет на замок. Два вызова через `Promise.all` могут пройти по очереди и ничего не доказать.
- **Список** — e2e листает все страницы и проверяет, что записей не потеряно и нет повторов.
- **Доступ** — e2e на запрос к чужому комплексу: ответ не раскрывает, что объект существует.

## Оснастка

- `useTestApp()` — всё приложение и база; перед каждым тестом база очищается. Для сценариев модулей.
- `createProbeApp([Controller])` — тестовый контроллер с настройками приложения, без `AppModule`. Модули, которые нужны тесту, в том числе базу, он подключает сам через `imports`. Для общего поведения: фильтр ошибок, журнал, guard, утечки в журнал.
- `responseBody<T>(response)` — единственный способ прочитать тело ответа: он проверяет, что в нём нет секретов. Намеренно отдаваемые поля называются в `allowKeys`.
- `defineFactory` — основа фабрик: значения по умолчанию плюс переопределения.
- `waitFor` — дождаться результата фоновой работы вместо паузы на фиксированное время.
- `runOverlapped` — две транзакции, которые обязаны пересечься; `planOf` — план запроса: какие таблицы прочитаны, чем и сколько строк.

Провайдер подменяется через `useTestApp((builder) => builder.overrideProvider(Clock).useValue(clock))`.

## Ограничения

- Приложение слушает `127.0.0.1` один раз на файл, и supertest получает готовый адрес.
  Если передать ему неслушающий сервер, он откроет свой порт на каждый запрос, и запрос может уйти в чужой процесс.
- e2e-файлы идут по одному: база общая.
- `cleanDatabase` работает только при `NODE_ENV=e2e`.
- Время в тестах — через подмену `Clock`, без `vi.useFakeTimers()` для дат предметной области.
- Тестовые данные выдуманы, и это видно по значению: `secret@example.com`, `+37300000000`.

## Проверяется автоматически

- oxlint: `.body` в `test/e2e/` запрещён.
- `cleanDatabase` отказывается работать вне `NODE_ENV=e2e`.

## Не проверяется

- Что у эндпоинта есть e2e на каждую ошибку и на чужой комплекс.
- Что правила entity покрыты unit-тестами.
