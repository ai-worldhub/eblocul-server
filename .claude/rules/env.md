# Переменные окружения и секреты

## Откуда читаются

| `NODE_ENV`   | Файлы                          | Где                             |
| ------------ | ------------------------------ | ------------------------------- |
| `lab`        | `.env.local`, затем `.env.lab` | локально и на lab-сервере       |
| `production` | `.env.production`              | production                      |
| `e2e`        | `.env.e2e`                     | тесты; в CI — переменные задачи |

В git попадает только `.env.example`. Остальные `.env.*` закрыты `.gitignore`.

## Новая переменная

Добавляется сразу в три места:

1. `EnvironmentVariables` в `src/shared/configs/env.validation.ts` — с декораторами проверки. Приложение не стартует, если переменной нет или она неверна.
2. `.env.example` — с безопасным значением; у секрета значение пустое и подсказка, как его получить.
3. `vitest.config.e2e.ts` — выдуманное значение, если переменная обязательна.

Переменная, которую читает не приложение, а инструмент (например `FORCE_COLOR`), вносится в `.env.example` и в список `TOOL_VARIABLES` теста `test/unit/configs/env-example.spec.ts`.

Код в `src/` читает переменные только через `ConfigService`. `process.env` напрямую — только в
`src/shared/configs/`, а вне `src/` — в `prisma.config.ts`, конфигах инструментов и тестах.

## Что считается секретом

- токены, коды входа и SMS-коды;
- пароли и их хэши;
- ключи внешних сервисов, соли и ключи шифрования;
- адрес базы и внутренних сервисов;
- имена бакетов, ключи объектов и подписанные ссылки хранилища;
- текст ошибок библиотек: в нём бывают запросы, адреса и аргументы вызова.

## Где секретов быть не должно

Ответы API, `details` ошибок, журнал, примеры в Swagger, тестовые данные, коммиты.
В тестах и CI — только выдуманные значения, по которым видно, что они не настоящие:
`e2e-auth-jwt-secret-not-a-real-key`.

## Если секрет утёк

1. Он считается раскрытым и сразу заменяется.
2. Об этом сообщают владельцу проекта.
3. Убирается причина утечки.

Историю git не переписывают: это не отменяет утечку.

## Проверяется автоматически

- Запуск приложения: `validateEnv` отклоняет отсутствующую или неверную переменную. Обязательная переменная, забытая в `vitest.config.e2e.ts`, роняет e2e на старте.
- `test/unit/configs/env-example.spec.ts`: в `.env.example` есть каждая переменная из `EnvironmentVariables`, нет лишних и нет повторов.
- oxlint: в `test/e2e/` тело ответа читается только через `responseBody`, обращение к `.body` запрещено;
  в `src/` обращение к `process.env` запрещено везде, кроме `src/shared/configs/`.
- `responseBody`: тело ответа не содержит секретных полей, JWT, адресов базы и хранилища.
- Тесты журнала: маскировка полей с секретными именами.

## Не проверяется

- Секрет в поле с обычным именем; секреты в примерах Swagger.
