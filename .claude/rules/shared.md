# `app/` и `shared/`

## Что лежит в `src/`

- `app/` — сборка приложения;
- `shared/` — общее без предметной области;
- `generated/` — клиент Prisma, создаётся `prisma generate`, руками не правится и в git не попадает;
- `main.ts` — точка входа процесса API;
- `worker.ts` — точка входа процесса исполнителей заданий, без HTTP;
- `seed.ts` — точка входа команды наполнения базы `lab`, без HTTP;
- `core/` — модули ядра, по папке на модуль;
- `modules/` — прикладные модули, по папке на модуль.

## Направление зависимостей

`app → modules → core → shared`. `shared/` не импортирует ни модули, ни `app/`.
Модули не импортируют `app/`. Границы между модулями — в `modules.md`.

## `app/` — только сборка

Здесь лежит то, что знает обо всех модулях сразу:

- `app.module.ts` — список модулей;
- `worker.module.ts` — `AppModule` и исполнители заданий со списком обработчиков; его собирает `worker.ts`;
- `job-handlers.ts` — общий список обработчиков заданий всех модулей: только импорты и массив;
- `access-actions.ts` — общий список действий доступа всех модулей: только импорты и массив;
- `journal-actions.ts` — общий список типов действий журнала всех модулей: только импорты и массив;
- `seed.module.ts` — `AppModule` и запуск сидов со списком; его собирает `seed.ts`;
- `lab-seeds.ts` — общий список сидов всех модулей: только импорты и массив;
- `app.setup.ts` — префикс, валидация, фильтр ошибок, OpenAPI-документ;
- `error-statuses.ts` — реестр таблиц «код ошибки → статус» всех модулей.

Логики, DTO и помощников в `app/` нет. То, что нужно модулям, лежит в `shared/`.

## `shared/` — общее без предметной области

| Папка      | Что даёт                                                           |
| ---------- | ------------------------------------------------------------------ |
| `configs/` | чтение и проверка переменных окружения                             |
| `db/`      | `DbService` — клиент Prisma, `Transactions` — транзакции, тип `Tx` |
| `logging/` | `EventLogger`, id запроса, маскировка секретов                     |
| `http/`    | формат ошибки, валидация, `ListQuery`, курсор, пометки эндпоинтов  |
| `clock/`   | `Clock` — текущее время                                            |
| `ids/`     | `Ids` — id записей                                                 |
| `health/`  | `GET /api/v1/health`                                               |
| `seeding/` | `LabSeed` — основа сида, `SeedRunner` — запуск списка сидов        |

`ConfigService`, `DbService`, `Transactions`, `EventLogger`, `Clock` и `Ids` объявлены глобально: модуль
внедряет их через конструктор и ничего не импортирует в своём `*.module.ts`.

## Что можно класть в `shared/`

Все три условия сразу:

1. В коде нет знаний о предметной области: ни названий сущностей, ни их таблиц, ни их правил.
2. Код полезен любому модулю, а не одному конкретному. То, что нужно только одному модулю, остаётся в нём.
3. У вещи своя подпапка. Файлов в корне `shared/` нет, папки `utils` нет.

Папка внутри `shared/` может импортировать соседнюю: `http/` пользуется `logging/`.

## Проверяется автоматически

oxlint:

- файл в `shared/` импортирует только `shared/` и `generated/`;
- файл модуля не импортирует `app/`;
- `nestjs-pino`, `pino` и `pino-http` импортируются только в `shared/logging/`, `main.ts`, `worker.ts` и `seed.ts`.

## Не проверяется

- Знания о предметной области в `shared/` и логика в `app/`.
- Файлы глубже двух уровней: `shared/http/dto/x.ts` и `modules/tickets/domain/thing/x.ts` проверяются, уровень ниже — нет.
