# Сиды

Сид — выдуманные данные для окружения `lab`: локальная база и lab-сервер.
В `production` сидов нет.

## Команда

- `npm run seed` — собирает проект и запускает сиды.
- `npm run seed:built` — запускает уже собранное (`dist/seed.js`); так команда запускается на lab-сервере.
- Команда работает только при `NODE_ENV` `lab` и `e2e`. В `production` она ничего не пишет и завершается с кодом 1.
- Сиды идут по порядку списка. Первый упавший останавливает запуск, код выхода — 1.

## Сид модуля

- Данные добавляет модуль, которому они принадлежат. Сид — класс в `application/seeds/<что>.seed.ts`, наследует `LabSeed`.
- `name` — `<модуль>.<что>`: `structure.test_house`. Два сида с одним именем не запускаются.
- Сид — провайдер своего модуля, открыт через `index.ts` и внесён в общий список `src/app/lab-seeds.ts`.
- В списке только импорты и массив классов. Порядок в массиве — порядок запуска: сначала то, на что ссылаются остальные.
- Сид создаёт данные через сервисы своего модуля, а не запросами в обход: действуют те же правила entity, время из `Clock`, id из `Ids`.
- Повторный запуск безопасен: сид сначала проверяет, есть ли уже его данные, и дублей не создаёт.
- Данные выдуманы, и это видно по значению: `+37360000000`, `admin@example.com`. Настоящих людей, телефонов и адресов в сидах нет.
- Телефон в сиде записан по правилу номера страны: иначе по нему не войти.
- На данные чужого сида сид ссылается константой, которую владелец открыл в своём `index.ts`: `TEST_ADMIN`, `TEST_HOUSE`.
  Литерал чужого сида — email, название — не повторяется.
- Аккаунты сидов с паролем берут один пароль — из `SEED_ADMIN_PASSWORD`.

```ts
@Injectable()
export class TestHouseSeed extends LabSeed {
    readonly name = 'structure.test_house';

    constructor(private readonly _houses: HouseService) {
        super();
    }

    async run(): Promise<void> {
        if (await this._houses.existsByName(TEST_HOUSE_NAME)) {
            return;
        }
        await this._houses.create({ name: TEST_HOUSE_NAME });
    }
}
```

## Проверяется автоматически

- `test/unit/seeding/lab-seeds-registry.spec.ts`: каждый сид из `*.seed.ts` есть в `src/app/lab-seeds.ts`,
  в списке нет лишнего и нет повторов.
- `test/unit/seeding/seedable-environment.spec.ts`: `production` отклоняется.
- `test/e2e/seeding/seed-runner.e2e-spec.ts`: порядок запуска, остановка на первом упавшем, отказ при двух одинаковых именах.
- Запуск команды: сид из списка — провайдер какого-то модуля.

## Не проверяется

- Что повторный запуск не создаёт дублей.
- Что сид пишет через сервисы своего модуля, а не напрямую в таблицы.
- Логика в `lab-seeds.ts`; имя сида с префиксом чужого модуля.
- Настоящие персональные данные в сидах.
