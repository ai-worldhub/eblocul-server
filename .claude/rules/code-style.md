# Стиль кода

## Язык

Всё в коде на английском: имена, сообщения ошибок, описания в Swagger.
Текст ошибки пользователю показывает клиент по её коду.

## Комментарии

Комментариев в коде нет: ни пояснений, ни JSDoc, ни TODO, ни закомментированного кода.
Причина неочевидного решения пишется в сообщении коммита или в правиле.
Директивы `oxlint-disable` и `@ts-expect-error` тоже не пишутся: исправляется причина.

## Имена файлов

kebab-case, вид файла — суффиксом через точку:
`house.service.ts`, `house.controller.ts`, `house.dto.ts`, `house.entity.ts`,
`house.repository.ts`, `house.errors.ts`, `house.error-statuses.ts`,
`house.log-events.ts`, `house.spec.ts`, `house.e2e-spec.ts`.
Файл без подходящего вида называется по содержимому: `pretty-logs.ts`.

## Имена в коде

- Классы и типы — PascalCase; у entity суффикс `Entity`.
- Константа уровня модуля с фиксированным значением — UPPER_SNAKE_CASE, будь то
  примитив, список значений или таблица: `TIMEOUT_MS`, `LOG_FORMATS`, `ERROR_STATUSES`.
  У числа единица измерения стоит в имени.
- Функции и значения, вычисленные при запуске, — camelCase.
- Внедрённая зависимость в поле — с подчёркиванием: `private readonly _events: EventLogger`.
- Чисел и строк «из воздуха» в логике нет: значение вынесено в именованную константу в начале файла.

## Импорты и экспорты

- Импорты только относительные и с расширением `.ts`. Алиасов путей нет: на относительных путях стоят правила границ в линте.
- Тип импортируется через `import type`.
- Экспорты именованные. `export default` — только там, где его требует инструмент: конфиги и global setup.

## Функции и классы

- Класс — только для того, что создаёт Nest, для entity, ошибок и DTO. Всё остальное — функции.
- Функции вне классов — стрелочные константы; у экспортируемых тип возврата указан явно. Колбэки тоже стрелочные.

```ts
export const toCursorPage = <T>(rows: T[], limit: number): CursorPage<T> => {
    return { items: rows.slice(0, limit), nextCursor: null };
};
```

## Типы

- Форма данных — `type`. `interface` — только когда его расширяют из других файлов, как `LogEvents`.
- `any` и `!` не используются. Неизвестное значение — `unknown` и проверка.
- Приведение `as` — только на границе с внешними данными: результат `JSON.parse`,
  тело ответа в тесте, объект из библиотеки без типов. `as const` сюда не относится.
- `enum` TypeScript не используется. Значения из базы — `enum` в схеме Prisma и union-тип в `domain/`;
  значения не из базы — массив `as const` и union из него.

```ts
const LOG_FORMATS = ['json', 'pretty'] as const;
type LogFormat = (typeof LOG_FORMATS)[number];
```

## «Значения нет»

- Поле есть, но пустое — `null`, как в базе и JSON.
- Необязательный вход — `поле?: T`.
- `undefined` как значение не хранится и не отдаётся в ответе.
- Условие пишется явно: `value === null`, а не `!value`.

## Проверяется автоматически

- oxlint: стрелочные функции, запрет `any`, `!` и `console`, явные условия, незавершённые промисы,
  `type` вместо `interface` (кроме `*.log-events.ts`), запрет `export default` (кроме `test/setup/`).
- `tsc`: `import type`, расширение `.ts` в импортах.

## Не проверяется

Комментарии и директивы отключения, имена файлов и констант, подчёркивание у зависимостей,
уместность `as`, `enum`, `null` вместо `undefined`, алиасы путей.
